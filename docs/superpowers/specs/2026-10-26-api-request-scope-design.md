# Scoped API request reuse

The user authorized API-loading follow-up and commit/merge into dev. Earlier performance work is delivered by PR134 at dev31db96c. Work continues in the existing task worktree, now using dev uv/Python3.14; minimum supported Python remains3.11.

Introduce `okama.data_request_scope()` as an optional outer context for related public operations. Scopes reuse one requests.Session per thread, preserve the existing retry/timeouts/TLS/error behavior, cache only successful symbol-metadata response text and close every owned session on exit, including failures. Cache keys include API class, API URL, endpoint, symbol, normalized dates and period; metadata text is decoded afresh by existing QueryData methods so callers cannot poison cached dictionaries. Bound metadata to256 entries/4MiB. Nested contexts borrow the outer scope. Scopes do not persist across calls, threads, processes or later contexts unless explicitly propagated within one ListMaker operation.

Asset and ListMaker constructors automatically use this context, so metadata/return-series calls for one asset reuse a connection without caller changes. ListMaker threads explicitly borrow the same operation scope but get separate Sessions. An explicit outer context can reuse metadata across subsequent frontier/Portfolio constructors. Time-series, live-price and search responses are never cached: in particular different USD.FX date ranges remain independent requests. No persistent metadata cache, blind currency-range reuse or credential/session sharing between threads.

Alternative global/TTL metadata caches introduce stale data across unrelated calculations; a global Session is not thread-isolated; blind timeseries caching changes date coverage. None are selected. Add no dependency or global runtime setting.
